The core process

How a photo becomes a verdict

PhoneTwo-angle photo

In-app camera only. The second angle fires on its own. SHA-256 fingerprint on the device.

ServerStateless API

Node and Express. Checks the hash, rate and spend limits, keeps nothing.

Vision modelClaude reports

Sonnet 5.5 answers fixed criteria in a strict schema, and flags screens and printouts.

Rules engineCode decides

Verified, Retake or Fix first. Status, deductible and reminders. No model involved.

ClaimFingerprints match

Shared photos must match the recorded hashes. A person decides.

Swapping the model can never change a payout rule: the engine is pure TypeScript with no I/O, shared by the server and the app.

Decisions that carry weight

What we chose, and why

The model never decides

It only answers “visible?” and “in order?”. Verdicts are code, so they're testable, explainable and stay If's rules.

Measured, not assumed

Every model or prompt change must pass a hand-labelled gate. We compared Sonnet, Opus and Haiku on 414 photos and chose Sonnet for speed (3.4 s median) at near-Opus agreement.

Cheating is designed out

Screens and printouts are always Retake, only in-app camera photos count, two angles per check, and fingerprints are matched at a claim.

Private by default

The server is stateless and stores no photos. If would keep only a verdict, a date and a hash per check.

A demo that can't break

The public web demo uses recorded results for licensed example photos, so it is instant, free and identical for every judge, even without an API key.

Built for everyone

Finnish, Swedish and English; voice guidance that turns on with a screen reader; distinct haptics; large text.
